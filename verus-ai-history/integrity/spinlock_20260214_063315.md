## Structural Overview

The verified exec code replaces `AtomicBool`-based interior mutability with a plain `bool` field
and `&mut self` methods for verification. This is a **sequential specification model** of the
spinlock protocol, not a runtime replacement. The original remains the runtime implementation.
The verification model is thoroughly documented in the file header with explicit trust boundaries,
scope limitations, and API divergence notes.

## Exec Logic Correctness

All executable logic in the verified model faithfully represents the original semantics:

- **`new()`**: Sets `locked = false` (original: `AtomicBool::new(false)`). Equivalent initial state.
- **`try_lock()`**: Checks `!self.locked`, sets `locked = true` on success. Models `compare_exchange(false, true)`.
- **`lock()`**: Delegates to `try_lock()`. Under preconditions (unlocked + wf), equivalent to the original's CAS succeeding on first attempt.
- **`unlock()`**: Sets `locked = false`. Models `store(false, Ordering::Release)` from `Drop for SpinlockGuard`.
- **`is_locked()`**: Pure observer, no side effects.

No arithmetic, control flow, or data structure changes affect runtime correctness beyond the documented abstraction from atomics to sequential booleans.
