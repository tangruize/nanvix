## Scope

The verified model covers two modules:
- `process_manager.rs` — inner `ProcessManagerInner` state machine (112 verified, 0 errors).
- `process_manager_unsafe.rs` — outer `ProcessManagerUnsafeState` wrapper (40 verified, 0 errors).

The original source is `src/kernel/src/pm/process/manager/mod.rs` (1982 lines), which contains
both `ProcessManagerInner` (lines 121–1523) and the outer `ProcessManager` wrapper (lines 1529–1982).
The original also imports an `unsafe` submodule (`src/kernel/src/pm/process/manager/unsafe.rs`, 804 lines)
which is verified by `process_manager_unsafe.rs`.

## Verification Approach

The verified model uses **abstraction-based verification**. Instead of verifying the original
Rust types directly (which depend on complex kernel subsystems: `RunningProcess`, `SleepingProcess`,
`LinkedList`, `ThreadManager`, `Vmem`, `ContextInformation`, etc.), it models the process manager's
**queue-level state machine** using abstract types:

- `running_pid: i32` instead of `running: Option<RunningProcess>`
- `ready_count: usize` + `ghost_ready: PidSet` instead of `ready: LinkedList<RunnableProcess>`
- `suspended_count: usize` + `ghost_suspended: PidSet` instead of `suspended: LinkedList<SleepingProcess>`
- `interrupted_count: usize` + `ghost_interrupted: PidSet` instead of `interrupted: LinkedList<InterruptedProcess>`
- `zombie_count: usize` + `ghost_zombies: PidSet` instead of `zombies: LinkedList<ZombieProcess>`

This approach verifies all queue-level invariants (partition, disjointness, kernel liveness,
PID monotonicity, overflow safety) while deferring thread-level details to trust boundaries (T1–T15).

## Verified Properties

The verification proves 152 functions total (112 inner + 40 unsafe) with 0 errors:

1. **Queue partitioning**: Every PID is in exactly one queue (running, ready, suspended, interrupted, zombie) at any time.
2. **Kernel liveness**: PID 0 is always in {running, ready}, never suspended/interrupted/zombie.
3. **PID monotonicity**: New PIDs are always fresh (≥ next_pid).
4. **Overflow safety**: All arithmetic on counts and PIDs is proven within bounds.
5. **Schedule correctness**: running↔ready swap preserves all invariants.
6. **Sleep/exit/terminate correctness**: All state transitions preserve queue partitioning and kernel liveness.
7. **Wakeup correctness**: suspended→ready transition with all edge cases covered.
8. **Message tracking**: Buffered message count correctly incremented/decremented.
9. **Machine-checked divergence**: exit/exit_thread invalidate wf(), preventing post-exit operations.
10. **Context switch correctness**: Stale-atomic PID comparison and quantum reset match original code.
