## Methodology

Compared original source `src/kernel/src/pm/process/state/mod.rs` against verified exec code
`verus/split/kernel/pm/process/state/process_state.rs`. The verified code is a **protocol-level
verification model** — it abstracts away complex kernel types (Vmem, EventOwnership, Mailbox,
IoMemoryRegion, AnyIoPort, Mutex/Arc, Condvar/Arc, BTreeMap, LinkedList) that Verus cannot verify,
replacing them with concrete Vec-based representations. Functions operating on opaque types are
modeled as `external_body` stubs with frame-condition postconditions proving they do not modify
verified state.

## Logic Correspondence Analysis

### get_mutex: Original vs Verified

**Original:**
```rust
if self.mutexes.len() >= MUTEX_OPEN_MAX { return Err(OutOfMemory); }
Ok(self.mutexes.entry(mutex_addr).or_insert_with(Mutex::new).clone())
```

**Verified:**
```rust
if self.mutex_count >= Self::MUTEX_MAX_EXEC() { return Err(OutOfMemory); }
if already_present { /* increment ref count */ Ok(old_rc + 1) }
else { /* insert with ref_count=2 */ Ok(2) }
```

**Assessment:** Faithful. The `entry().or_insert_with()` either returns existing (no growth) or
inserts new. `.clone()` on Arc-based Mutex increments strong_count. Verified code makes this
explicit. Initial ref_count=2 correctly models 1 in BTreeMap + 1 returned clone.

Note: Both versions share a known over-conservative behavior — the capacity check rejects
`get_mutex` for already-existing keys when at capacity, even though `entry()` wouldn't grow the map.
This is a latent design issue in the original (documented in `MutexCapacityBugReport.md`), and the
verified code faithfully replicates it.

### put_mutex: Original vs Verified

**Original:**
```rust
if !self.mutexes.contains_key(&mutex_addr) { return Err(NoSuchEntry); }
let _ = self.mutexes.extract_if(.., |&addr, mutex|
    mutex_addr == addr && mutex.reference_count() <= 2).collect();
Ok(())
```

**Verified:**
```rust
if !contains { return Err(NoSuchEntry); }
if ref_count_at_threshold { /* remove at idx */ self.mutex_count -= 1; }
Ok(())
```

**Assessment:** Faithful. `extract_if` with address match + ref_count threshold is equivalent to
conditional removal at the unique index. BTreeMap uniqueness guarantees at most one entry matches.

### put_cond: Threshold Difference

Original uses `reference_count() <= 1`; verified uses `COND_REMOVE_THRESHOLD() = 1`. Values match.
Original put_mutex uses `reference_count() <= 2`; verified uses `MUTEX_REMOVE_THRESHOLD() = 2`.
Values match.

### remove_pmio: Original vs Verified

**Original:**
```rust
let index = self.pmio.iter().position(|p| p.number() == port_number);
match index { Some(i) => Ok(self.pmio.remove(i)), None => Err(NoSuchEntry) }
```

**Verified:**
```rust
if !found { return Err(NoSuchEntry); }
self.pmio_ports.remove(found_idx); Ok(())
```

**Assessment:** Faithful. Position-based first-occurrence removal preserved. Return type difference
(AnyIoPort vs ()) is justified — AnyIoPort is opaque in the verification model.

### ProcessRefMut / ProcessRef

Original: enums with lifetime parameters wrapping references to process state variants.
Verified: opaque structs with `external_body` stubs. These are lifecycle accessor wrappers
that don't contain verifiable logic — they delegate to `state()` / `state_mut()`.
