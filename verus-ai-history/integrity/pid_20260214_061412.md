## Semantic Equivalence Notes

### Conversion Logic
All `TryFrom`/`TryInto` implementations in the verified code use explicit range
checks instead of Rust's `try_into()`. This is necessary because Verus cannot
reason about `TryFrom` trait method semantics. The explicit checks are provably
equivalent:
- **i32 → usize/u32/u64:** Fails iff `value < 0` (same as `i32::try_into()` for unsigned types).
- **isize/i64 → i32:** Fails iff `raw < i32::MIN || raw > i32::MAX` (same as `try_into()` for narrowing signed conversions).
- **usize/u32/u64 → i32:** Fails iff `raw > i32::MAX` (same as `try_into()` for unsigned-to-signed conversions; unsigned values are always ≥ 0).

### Struct Layout
The verified struct uses `#[repr(C)]` with a single `i32` field, matching the
original's `#[repr(C)]` tuple struct layout. Layout equivalence is further
asserted by `lemma_size_eq_i32` and `lemma_align_eq_i32` proof lemmas (both 4
bytes size and alignment).

### Trust Boundaries
Two `external_body` annotations on exec functions:
1. `to_ne_bytes` — delegates to `i32::to_ne_bytes()`.
2. `from_ne_bytes` — delegates to `i32::from_ne_bytes()`.

These are justified by Rust's documented round-trip guarantees for native-endian
byte serialization. Three proof axioms (`axiom_byte_roundtrip`,
`axiom_decode_encode_roundtrip`, `axiom_from_ne_bytes_in_range`) document the
assumed properties.
