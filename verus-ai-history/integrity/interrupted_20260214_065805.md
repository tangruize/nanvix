## Detailed Exec Logic Comparison

### `from_state()`
- **Original:** `Self { state, reason }` where `state: Box<ThreadState>`, `reason: InterruptReason`.
- **Verified:** `InterruptedThread { state: state, reason: reason }` where `state: ThreadState`, `reason: int`.
- **Verdict:** Identical logic — direct field assignment. Type changes documented above.

### `id()`
- **Original:** `self.state.id()`
- **Verified:** `self.state.id()`
- **Verdict:** Identical.

### `thread_state()`
- **Original:** `&self.state` (returns `&ThreadState` — Box auto-derefs)
- **Verified:** `&self.state`
- **Verdict:** Identical.

### `thread_state_mut()`
- **Original:** `&mut self.state` (returns `&mut ThreadState` — Box auto-derefs)
- **Verified:** `&mut self.state` (marked `#[verifier::external]`)
- **Verdict:** Identical logic. External annotation is a Verus limitation, not a logic change.

### `resume()`
- **Original:**
  ```rust
  pub fn resume(mut self) -> ReadyThread {
      self.state.set_interrupt_reason(self.reason);
      ReadyThread::from_state(self.state)
  }
  ```
- **Verified:**
  ```rust
  pub fn resume(self) -> (result: ReadyThread)
      requires self.wf(),
      ensures ...
  {
      let reason_value: int = self.reason;
      let mut state: ThreadState = self.state;
      state.set_interrupt_reason(reason_value);
      ReadyThread::from_state(state)
  }
  ```
- **Verdict:** Semantically identical. The verified version destructures `self` into local variables (`reason_value`, `state`) rather than using `mut self`, but the operations are the same: extract reason, call `set_interrupt_reason` on state, wrap in `ReadyThread`. The local-variable approach is a Verus idiom (Verus prefers explicit bindings for spec reasoning).

### `join_cond()`
- **Original:** `self.state.join_cond()` — returns `Condvar`.
- **Verified:** Omitted.
- **Verdict:** `Condvar` is an opaque sync primitive not modeled in the verification. Documented trust boundary.
