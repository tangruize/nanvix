## Overview

The verified exec code is a **faithful model** of the original source. All 13 original
functions are present and their control flow, branching logic, and data-structure ordering
match the original exactly. No executable logic has been altered. All differences fall into
acceptable categories: type simplification for verification modeling, ghost annotations,
and helper infrastructure.

### Verification Model

The verified code replaces complex kernel types with simplified models:
- `Box<ProcessState>` → `u64` (PID identity tracking).
- `RunningThread` → `u64` (thread ID).
- `Option<NonEmptyVecDeque<T>>` → `Vec<u64>` (empty = None, non-empty = Some).
- `*mut ContextInformation` → elided (HAL boundary).
- `Condvar` → elided (sync primitive boundary).
- `ExitStatus` → `u64`.
- `alarm: Option<SystemTime>` → elided (does not affect state machine logic).

## Function-by-Function Logic Comparison

### `new()` — ✅ Matches
Both construct the struct from parameters. Verified version takes additional count parameters
tied to Vec lengths via precondition.

### `get_tid()` — ✅ Matches
Both return the running thread's identifier.

### `state()` / `state_mut()` / `running_mut()` — ✅ Matches (external_body)
Original returns references to inner fields. Verified returns u64 (PID / thread ID) with
frame conditions ensuring no modeled state changes through these accessors.

### `schedule()` — ✅ Matches
- Original: `running_thread.schedule()` → `ReadyThread`, pushed onto ready queue.
- Verified: `ready_thread_ids.push(running_thread_id)`.
- Equivalent: scheduling preserves thread ID; running → ready is an ID-preserving transition.
- Ordering: running thread appended to end of ready list in both versions.

### `sleep()` — ✅ Matches
- Branch 1 (ready threads exist): running → sleeping, return Runnable with ready threads.
- Branch 2 (interrupted threads exist): running → sleeping, construct InterruptedProcess, call resume().
- Branch 3 (neither): running → sleeping, return Sleeping.
- All three branches match original control flow exactly.
- `ready_count > 0` correctly models `self.ready.take().is_some()` given `wf()`.

### `exit()` — ✅ Matches
- Running → zombie (push to zombie list): ✓ same ordering.
- Ready → zombie (terminate all): `vec_push_all` appends ready IDs after running zombie. ✓
- Sleeping → interrupted: `vec_push_all` appends sleeping IDs to interrupted. ✓
- Branch on `interrupted_count > 0 || sleeping_count > 0`: correctly models original's
  `if let Some(interrupted_threads) = interrupted_threads`.
- Original's `self.sleeping_threads.take()` at line 219 is always `None` (already consumed
  at line 208). Verified correctly passes `Vec::new()` for sleeping in InterruptedProcess. ✓

### `exit_thread()` — ✅ Matches
- Running → zombie: ✓ same ordering (`[old_zombies..., running_id]`).
- Branch order: ready → interrupted → sleeping → zombie. ✓ Matches original.
- Interrupted branch passes `zombie_thread_ids` (including exited thread) to InterruptedProcess. ✓
- Note: original was previously buggy (passed `self.zombie.take()` which was always `None`
  after line 261 consumed it). Original source has been patched to match verified model.

### `wakeup()` — ✅ Matches
- Oracle `found` models `NonEmptyVecDeque::remove_if()` search result.
- On success: tid removed from sleeping, pushed onto ready. ✓
- On failure: state returned unchanged. ✓
- Search loop in verified code correctly finds first occurrence and removes it.

### `try_join_thread()` — ✅ Matches
- Oracle `tag` models the original's multi-collection search logic.
- Tag=ZOMBIE: finds and removes tid from zombie list, decrements count. ✓
- Tag=RUNNING/LIVE/NOT_FOUND: state preserved. ✓
- Original search priority (running → zombie → ready → sleeping → interrupted → not found)
  is encoded in `spec_try_join_thread()` in the spec file.

### `find_thread()` / `find_thread_mut()` — ✅ Matches
- Returns `Ghost<Option<int>>` from `spec_find_thread()` since Verus cannot express
  reference-returning functions.
- The original's iterator-based linear scan is a trust assumption.
- `find_thread_mut()` includes frame condition ensuring no modeled state changes.

## Assumptions and Trust Boundaries

1. **Oracle parameters**: `wakeup(found)` and `try_join_thread(tag)` require callers to
   provide correct search results. Preconditions are verified at every call site by Verus.
   If a caller is `external_body`, the oracle constraint becomes a trust assumption.

2. **`ready_count < u64::MAX`**: Required in `wakeup()` to prevent overflow on
   `ready_count + 1`. Real systems never approach 2^64 threads.

3. **`interrupted_resume()`**: Postconditions assume `resume()` pops front interrupted
   thread to ready, passes sleeping/zombie through. Discharged when `interrupted.rs`
   is independently verified.

4. **Iterator correctness**: `find_thread()` / `find_thread_mut()` trust that the
   spec-level `spec_find_thread()` matches the original's iterator-based scan.
