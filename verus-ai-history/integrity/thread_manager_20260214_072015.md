## Overview

The verified exec code in `verus/split/kernel/pm/thread/thread_manager.rs` faithfully models
the original `src/kernel/src/pm/thread/mod.rs`. No executable logic changes were found. All
differences are either ghost annotations (requires/ensures/invariants) or type-level
simplifications necessitated by Verus limitations (no lifetime-parameterized enums, no `&mut T`
return types, no HAL boundary types). The core control flow — ID assignment, monotonic
increment, kernel thread initialization, and dispatch logic — is identical between the original
and the verified model.

## Logic Integrity Assessment

The core executable logic is **identical** between original and verified:

| Function | Original Logic | Verified Logic | Match |
|----------|---------------|----------------|-------|
| `new()` | Create kernel thread with ID 0, return manager with next_id=1 | Same | ✅ |
| `create_thread()` | Copy next_id → id, increment next_id by 1, create thread with id | Same | ✅ |
| `init()` | Delegate to `ThreadManager::new()` | Same | ✅ |
| `thread_state()` | Match on 5 variants, return state | Same (direct return instead of method call) | ✅ |
| `thread_state_mut()` | Match on 5 variants, return mutable state | Same dispatch, modeled read-only | ✅ (trust boundary) |

## Trust Boundaries

1. **HAL types elided**: `ContextInformation`, `FpuState`, `KernelStack`, `UserStack`, `VirtualAddress` are replaced with abstract tokens (`int`). Verification of HAL interaction is out of scope.
2. **Mutable return types**: `thread_state_mut()` modeled as read-only. Callers must preserve `wf()` and `spec_id()` after mutation.
3. **ReadyThread boundary model**: Postconditions assumed to match real `ReadyThread::new()` spec. Cross-module check documented.
4. **Heap allocation**: `Box::new` assumed to succeed (original panics on OOM).
5. **Single initialization**: `init()` assumed to be called exactly once (original has TODO for this).
