## Key Technical Challenges

1. **Closed `view()` spec**: `Slab::view()` is a `closed spec fn`, preventing the prover from
   automatically connecting `allocated_blocks.contains(j)` with `index.is_bit_set(num_index_blocks + j)`
   in standalone lemmas. Fixed by adding explicit `is_bit_set` triggering assertions in `by` bodies.

2. **Trigger matching for `lemma_inv_from_components`**: This existing lemma uses
   `#![trigger slab.index@.set_bits.contains(i)]` in its precondition. The dealloc lemma needed to
   assert `set_bits.contains(j)` (not just `is_bit_set(j)`) to match this trigger pattern.

3. **Verus parser quirk**: Expressions like `slab.field as int < slab.other` cause parse errors
   because the parser interprets `<` as a generic type parameter bracket. Fixed by parenthesizing
   all `as int` casts: `(slab.field as int)`.

4. **Low-confidence trigger warnings**: Two `assert forall` expressions in
   `lemma_alloc_establishes_postconditions` and `lemma_dealloc_clear_ok_postconditions` triggered
   Verus low-confidence trigger warnings. Fixed by adding `#![auto]` annotations to accept the
   automatically chosen triggers.
