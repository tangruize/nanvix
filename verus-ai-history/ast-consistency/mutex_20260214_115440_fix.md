# Exec Consistency Fix: mutex

## Summary
- Mismatches fixed: 0 (all 3 documented as Verus limitations)
- Missing functions added: 2 (`reference_count`, `unlock_unchecked`)
- Documented equivalences: 5

## Changes

| Function | Action | Justification |
|----------|--------|---------------|
| `new` | Documented equivalence | Original creates `Arc<MutexInner>` with `AtomicBool`; Verus uses plain `bool` + `id` param for instance identity. Verus cannot model `AtomicBool`, `Arc`, or `Condvar`. The `id` parameter replaces `Arc` reference identity (Trust Assumption T1). Semantically equivalent: both produce an unlocked mutex. |
| `try_lock` | Documented equivalence | Original uses `compare_exchange(false, true)` on `AtomicBool` with `&self`; Verus uses `if !self.locked { self.locked = true }` with `&mut self`. Sequential model of atomic CAS — equivalent for single-threaded state machine. `&mut self` required because Verus needs exclusive references for mutation (no interior mutability). |
| `lock` | Documented equivalence | Original loops `try_lock()` + `Condvar::wait()` with timeout; Verus calls `try_lock()` once. Precondition `is_unlocked()` guarantees success on first attempt. The loop/sleep/timeout behavior models concurrent contention which is out of scope for sequential verification. |
| `reference_count` | Added | Returns `1usize` in the sequential model. Original returns `Arc::strong_count()`. Without `Arc`, there is exactly one owner. |
| `unlock_unchecked` | Added | Private helper modeling `MutexInner::unlock_unchecked()`. Sets `locked = false` and `token_issued = false`. Original also calls `notify_first()` (Condvar, external dependency not modeled). `unlock()` now delegates to this, mirroring the original `Drop` → `unlock_unchecked` call chain. |
| `fmt` | Not added | Verus does not support `fmt::Debug` trait implementations. Display-only function with no state mutation — outside verification scope. |
| `drop` | Not added | Verus does not support `Drop` trait implementations. Modeled via explicit `unlock()` with `MutexToken` consumption (RAII replacement). |
| `unlock` | Kept (extra) | Models `MutexGuard::drop()` from original. Consumes `MutexToken` and delegates to `unlock_unchecked()`. Essential for verification — replaces RAII `Drop` pattern. |
| `is_locked` | Kept (extra) | Verification-only helper for spec predicates. Documented in API Mapping table. |
| `Mutex` struct | Documented equivalence | Original: `Mutex(Arc<MutexInner>)` wrapper. Verus: `Mutex { locked, id, token_issued }`. Flattened because `Arc`/`MutexInner` not modelable; `id` replaces reference identity; `token_issued` tracks ghost state. |
| `MutexGuard` struct | Not added | Replaced by tracked `MutexToken` ghost struct. Verus cannot model `Drop`-based RAII; explicit token consumption in `unlock()` provides equivalent proof obligation. |
| `MutexInner` struct | Not added | Flattened into `Mutex`. No `Arc` shared ownership to model; fields (`locked`) are directly on `Mutex`. |
