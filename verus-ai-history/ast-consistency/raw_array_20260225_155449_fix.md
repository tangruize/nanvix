## Detailed Equivalence Analysis

### `drop` — Structural Relocation (Verus Limitation)

**Source** (`impl Drop for RawArray<T>`):
```rust
fn drop(&mut self) {
    match &self.storage {
        RawArrayStorage::Managed { ptr, len } => { /* dealloc */ },
        RawArrayStorage::Unmanaged { .. } => (),
    }
}
```

**Verus** (`impl Drop for RawArrayStorage<T>`):
```rust
fn drop(&mut self) {
    match self {
        RawArrayStorage::Managed { ptr, len } => { /* dealloc */ },
        RawArrayStorage::Unmanaged { .. } => (),
    }
}
```

**Why equivalent**: In Rust, when a struct is dropped, all its fields are dropped after the custom `Drop::drop` runs. In the source, `RawArray::drop` deallocates the storage, then `RawArrayStorage` (which has no `Drop` impl) is trivially dropped. In the verus version, `RawArray` has no `Drop` impl, so Rust auto-drops its `storage` field, triggering `RawArrayStorage::drop` which performs identical deallocation. The deallocation code body is identical in both versions.

**Why necessary**: Verus requires `RawArray` to be defined inside `verus!{}` for verification, but trait impls like `Drop` cannot be placed inside `verus!{}` blocks.

### `get` — False Positive (Different Types)

The AST tool matched by function name across file boundaries, but the source `get` is `RawArrayStorage::get(&self) -> &[T]` while the verus `get` is `RawArray::get(&self, index: usize) -> &T`. The source's `RawArrayStorage::get` is present unchanged in verus (lines 98-106). The verus `RawArray::get` is an additional verified accessor.
