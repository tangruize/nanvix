## Notes

All five mismatched functions have exec logic that is **semantically equivalent** to the
original but structurally different due to Verus limitations:

1. **AtomicU32 → plain u32**: Verus cannot reason about `core::sync::atomic` types.
   The sequential model is valid under the documented single-writer assumption (T1).
2. **wrapping_add → explicit branching**: Verus cannot reason about `wrapping_add`.
   Equivalence is formally proved by `lemma_wrapping_add_equiv` (T2).
3. **`<< 32` → `* 0x1_0000_0000`**: Verus has limited bitwise shift reasoning.
   `x << 32 == x * 2^32` is a mathematical identity.
4. **`#[cfg]` → parameters**: Verus cannot model conditional compilation.
   Both cfg paths are covered by separate model functions.
5. **External types → primitives**: `SystemTime` and `InterruptNumber` are external
   to the verification scope. Return types use `(u64, u32)` pairs instead.

No exec logic was actually changed — all divergences preserve the original arithmetic
and control flow. The `timer_handler` function cannot be directly ported (HAL/unsafe
dependencies) and is covered by the `timer_handler_model()` verified behavioral model.
