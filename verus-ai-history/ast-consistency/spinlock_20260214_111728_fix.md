## Detailed Equivalence Analysis

### Why exec logic was NOT restored

All divergences stem from fundamental Verus limitations that make direct translation impossible:

1. **`AtomicBool` → `bool`**: Verus has no model for `core::sync::atomic`. The sequential `bool` model verifies the state machine protocol (lock/unlock transitions). Concurrency/atomicity is explicitly out of scope (see "Verification Scope" in module docs).

2. **`&self` → `&mut self`**: Verus requires exclusive references for state mutation. The original's `&self` is safe due to `AtomicBool` interior mutability, which Verus cannot model. This is documented in "API Divergence" section.

3. **`SpinlockGuard`/`Drop` → `LockToken`/`unlock()`**: Verus cannot reason about `Drop` trait implementations or lifetime-bound RAII. The ghost `LockToken` pattern makes the lock-release obligation explicit and verifiable. `lemma_unlock_models_drop` formally proves the state equivalence.

4. **`id` parameter in `new()`**: Verus cannot reason about reference identity (`&'a Spinlock`). The `id` field provides explicit instance identity for token isolation. Documented as Trust Assumption T1.

5. **CAS loop → `try_lock()` delegation**: The sequential model's `is_unlocked()` precondition guarantees first-attempt success, making the spin loop unnecessary. The loop's purpose (retry under contention) is a concurrency concern outside the sequential verification scope.
