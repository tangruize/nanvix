| `RawArray` struct | Fixed: restored doc comment on `storage` field | The Verus version was missing `/// The backing storage of the raw array.` on the `storage` field. Restored to match source. |
| `RawArray::drop` (MISSING_IN_VERUS) | Documented equivalence | Cannot add `Drop for RawArray<T>` because RawArray is defined inside `verus!{}` and Verus does not support trait impls there. The existing `Drop for RawArrayStorage<T>` is semantically equivalent: when RawArray is dropped, Rust automatically drops the `storage` field, triggering `RawArrayStorage::drop` with identical deallocation logic. Adding both would cause double-free. |

| `RawArray::set/len/get` (EXTRA_IN_VERUS) | Kept: justified | Verification helpers not in source. In the source, element access uses `Deref`/`DerefMut` to get a slice. Verus cannot verify through trait dispatch, so these `external_body` helpers provide verified accessors with `requires`/`ensures` contracts. Already documented in-code. |
| `ExRawArrayStorage` (EXTRA_IN_VERUS) | Kept: justified | Required by Verus `#[verifier::external_type_specification]` to create a spec-level wrapper for the `RawArrayStorage` type defined outside `verus!{}`. This is a standard Verus pattern for external types. |
