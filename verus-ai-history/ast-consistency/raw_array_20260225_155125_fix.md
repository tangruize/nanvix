## Detail: Verus Limitations Requiring Structural Changes

### Drop on RawArrayStorage (not RawArray)
Verus does not support `Drop` trait implementations inside `verus!{}` blocks.
Since `RawArray` is defined inside `verus!{}` (needed for spec/proof), the `Drop`
impl was moved to `RawArrayStorage` which lives outside `verus!{}`. Equivalence:
- Source: `impl Drop for RawArray<T>` → `match &self.storage { Managed{..} => dealloc, Unmanaged{..} => () }`
- Verus: `impl Drop for RawArrayStorage<T>` → `match self { Managed{..} => dealloc, Unmanaged{..} => () }`
- When `RawArray` is dropped, Rust drops its `storage: RawArrayStorage<T>` field,
  which triggers the `RawArrayStorage::drop()` with identical deallocation logic.

### Accessor helpers (get, set, len, storage_len)
Verus cannot verify exec code that goes through `Deref`/`DerefMut` trait dispatch.
In the source, element access is done via `self[i]` or `self.storage.get()[i]` through
slice dereferencing. In Verus, explicit `get`/`set`/`len` methods with
`requires`/`ensures` contracts provide verified alternatives. The underlying exec
logic delegates to the same `RawArrayStorage::get()`/`get_mut()` methods.
