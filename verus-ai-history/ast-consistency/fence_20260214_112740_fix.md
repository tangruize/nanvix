## Notes

All exec-level divergences are necessitated by fundamental Verus limitations:

1. **No `AtomicUsize` support**: Verus lacks a verification model for `core::sync::atomic` types.
   The sequential `usize` model verifies the state machine protocol (count ≤ total invariant,
   signal/wait transitions) without reasoning about atomicity or memory ordering.

2. **No `const fn` support**: Verus cannot verify `const fn` declarations.

3. **No interior mutability model**: Verus requires `&mut self` for state mutation; the original
   uses `&self` with `AtomicUsize` interior mutability.

4. **No blocking/spinning model**: The sequential model cannot express a spin-wait loop that
   terminates due to concurrent state changes from other threads.

All divergences are extensively documented in the file header sections: "Verification Model",
"API Divergence", "Trust Boundaries", and "Verification Scope". Each function also has inline
doc comments explaining its specific divergence from the original.
