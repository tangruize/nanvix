## Changes

### 1. `new()` - Error Case Specification

**Before:**
```rust
pub fn new(number_of_bits: usize) -> (result: Result<Self, Error>)
    ensures
        result is Ok ==> {
            let bitmap = result->Ok_0;
            &&& bitmap.inv()
            &&& bitmap@.number_of_bits() == number_of_bits as int
            &&& bitmap@.is_empty()
            &&& forall|i: int| 0 <= i < bitmap@.number_of_bits() ==> !bitmap.is_bit_set(i)
        },
```

**After:**
```rust
pub fn new(number_of_bits: usize) -> (result: Result<Self, Error>)
    ensures
        result is Ok ==> {
            let bitmap = result->Ok_0;
            &&& bitmap.inv()
            &&& bitmap@.number_of_bits() == number_of_bits as int
            &&& bitmap@.is_empty()
            &&& forall|i: int| 0 <= i < bitmap@.number_of_bits() ==> !bitmap.is_bit_set(i)
        },
        // Error case: at least one of these conditions must hold.
        // Note: RawArray::new may also fail, so we cannot fully enumerate error causes.
        (number_of_bits == 0 ||
         number_of_bits >= u32::MAX as usize ||
         number_of_bits % (u8::BITS as usize) != 0) ==> result is Err,
```

**Rationale:** The original spec only covered the success case. The strengthened spec adds that invalid arguments *always* produce errors. Note: we cannot add full liveness because `RawArray::new` can fail for allocation reasons beyond input validation.

### 2. `test()` - Error Case and Liveness

**Before:**
```rust
pub fn test(&self, index: usize) -> (result: Result<bool, Error>)
    requires
        self.inv(),
    ensures
        result is Ok ==> {
            &&& (index as int) < self@.number_of_bits()
            &&& result->Ok_0 == self.is_bit_set(index as int)
        },
        (index as int) < self@.number_of_bits() ==> result is Ok,
        // test is read-only - no state changes
```

**After:**
```rust
pub fn test(&self, index: usize) -> (result: Result<bool, Error>)
    requires
        self.inv(),
    ensures
        result is Ok ==> {
            &&& (index as int) < self@.number_of_bits()
            &&& result->Ok_0 == self.is_bit_set(index as int)
        },
        // Error case: out of bounds index produces error.
        result is Err ==> (index as int) >= self@.number_of_bits(),
        // Liveness: valid index always succeeds.
        (index as int) < self@.number_of_bits() ==> result is Ok,
        // test is read-only - no state changes
```

**Rationale:** Added explicit error case specification. The original had liveness but was missing the error characterization. Now both directions are covered: valid index ⟺ Ok result.

### 3. `index()` (private) - Error Case and Liveness

**Before:**
```rust
fn index(&self, index: usize) -> (result: Result<(usize, usize), Error>)
    requires
        self.inv(),
    ensures
        result is Ok ==> {
            let (word, bit) = result->Ok_0;
            &&& word < self.bits@.len()
            &&& bit < u8::BITS as usize
            &&& word == index / (u8::BITS as usize)
            &&& bit == index % (u8::BITS as usize)
            &&& index < self.bits@.len() * (u8::BITS as usize)
        },
        (index as int) < self@.number_of_bits() ==> result is Ok,
```

**After:**
```rust
fn index(&self, index: usize) -> (result: Result<(usize, usize), Error>)
    requires
        self.inv(),
    ensures
        result is Ok ==> {
            let (word, bit) = result->Ok_0;
            &&& word < self.bits@.len()
            &&& bit < u8::BITS as usize
            &&& word == index / (u8::BITS as usize)
            &&& bit == index % (u8::BITS as usize)
            &&& index < self.bits@.len() * (u8::BITS as usize)
        },
        // Error case: out of bounds index produces error.
        result is Err ==> (index as int) >= self@.number_of_bits(),
        // Liveness: valid index always succeeds.
        (index as int) < self@.number_of_bits() ==> result is Ok,
```

**Rationale:** Added explicit error case specification. Now errors only occur on out-of-bounds access, making the contract bidirectional.

## Functions Already Well-Specified

The following functions were reviewed and found to already have strong specifications:

- **`alloc()`**: Has both Ok/Err cases and liveness property `has_free_bit() ==> Ok`
- **`alloc_range()`**: Has both Ok/Err cases and liveness for size=1
- **`set()`**: Has both Ok/Err cases and liveness when bit is not set
- **`clear()`**: Has both Ok/Err cases and liveness when bit is set
- **`clear_range()`**: Has both Ok/Err cases and full liveness `result is Ok`
- **`from_raw_array()`**: Returns `Self` not `Result`, no error case needed
- **`number_of_bits()`**: Simple getter, no error case
- **`usage()`**: Simple getter, no error case

## Patterns Applied

1. **Bidirectional error specs**: `result is Err ==> condition` complements `condition ==> result is Err`
2. **Liveness properties**: Guarantees that operations succeed when preconditions are met
3. **Avoided over-specification**: Did not claim liveness for `new()` since underlying allocation can fail
