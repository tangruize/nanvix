## Changes

### 1. `Upool::new` - Bidirectional Fresh Initialization

**Issue:** One-sided implication for fresh initialization. Only stated that if the allocator is fresh, the result is fresh, but not the converse.

**Before:**
```rust
pub fn new(frame_allocator: FrameAllocator) -> (result: Upool)
    requires
        frame_allocator.inv(),
    ensures
        result.inv(),
        result@.capacity() == frame_allocator@.capacity,
        forall|i: int| 0 <= i < result@.capacity() ==>
            result@.is_allocated(i) == frame_allocator@.is_allocated(i),
        // Fresh initialization is preserved.
        frame_allocator@.is_freshly_initialized() ==> result@.is_freshly_initialized(),
```

**After:**
```rust
pub fn new(frame_allocator: FrameAllocator) -> (result: Upool)
    requires
        frame_allocator.inv(),
    ensures
        result.inv(),
        result@.capacity() == frame_allocator@.capacity,
        forall|i: int| 0 <= i < result@.capacity() ==>
            result@.is_allocated(i) == frame_allocator@.is_allocated(i),
        // Fresh initialization is preserved (bidirectional).
        result@.is_freshly_initialized() <==> frame_allocator@.is_freshly_initialized(),
```

**Rationale:** The bidirectional equivalence provides a complete specification. Callers can now reason in both directions: if input is fresh then output is fresh, AND if output is fresh then input was fresh. This prevents subtle bugs where non-fresh allocators could be incorrectly assumed to produce fresh pools.

### 2. `Upool::capacity` - Positivity Guarantee

**Issue:** Missing positivity guarantee. The invariant ensures capacity > 0, but this wasn't exposed in the ensures clause.

**Before:**
```rust
pub fn capacity(&self) -> (result: usize)
    requires self.inv(),
    ensures result as int == self@.capacity()
```

**After:**
```rust
pub fn capacity(&self) -> (result: usize)
    requires self.inv(),
    ensures
        result as int == self@.capacity(),
        // Capacity is always positive (from invariant).
        result > 0,
```

**Note:** This also required strengthening `FrameAllocator::capacity` in frame.rs with the same positivity guarantee:

```rust
// frame.rs - also strengthened
pub fn capacity(&self) -> (result: usize)
    requires self.inv(),
    ensures
        result as int == self@.capacity,
        // Capacity is always positive (from invariant).
        result > 0,
```

**Rationale:** Exposing the positivity guarantee (which is implied by the invariant) allows callers to use this fact without having to reason about invariant internals. This is especially useful for loop bounds and division operations.

### 3. `Upool::alloc_many` - Monotonicity Postcondition

**Issue:** Missing monotonicity guarantee. The loop invariant maintained that previously allocated frames remain allocated, but this wasn't exposed in the ensures clause.

**Before:**
```rust
pub fn alloc_many(&mut self, count: usize) -> (result: Ghost<Seq<int>>)
    requires
        old(self).inv(),
        count > 0,
        old(self).spec_num_allocated() + count as int <= old(self).spec_capacity(),
    ensures
        self.inv(),
        self@.capacity() == old(self)@.capacity(),
        result@.len() == count as int,
        forall|i: int| #![trigger result@[i]]
            0 <= i < result@.len() ==> { ... },
        forall|i: int, j: int| #![trigger result@[i], result@[j]]
            0 <= i < result@.len() && 0 <= j < result@.len() && i != j ==>
            result@[i] != result@[j],
        forall|i: int, j: int| #![trigger result@[i], result@[j]]
            0 <= i < result@.len() && 0 <= j < result@.len() && i != j ==>
            self@.frames_are_disjoint(result@[i], result@[j]),
        self.spec_num_allocated() == old(self).spec_num_allocated() + count as int,
```

**After:**
```rust
pub fn alloc_many(&mut self, count: usize) -> (result: Ghost<Seq<int>>)
    requires
        old(self).inv(),
        count > 0,
        old(self).spec_num_allocated() + count as int <= old(self).spec_capacity(),
    ensures
        self.inv(),
        self@.capacity() == old(self)@.capacity(),
        result@.len() == count as int,
        forall|i: int| #![trigger result@[i]]
            0 <= i < result@.len() ==> { ... },
        forall|i: int, j: int| #![trigger result@[i], result@[j]]
            0 <= i < result@.len() && 0 <= j < result@.len() && i != j ==>
            result@[i] != result@[j],
        forall|i: int, j: int| #![trigger result@[i], result@[j]]
            0 <= i < result@.len() && 0 <= j < result@.len() && i != j ==>
            self@.frames_are_disjoint(result@[i], result@[j]),
        self.spec_num_allocated() == old(self).spec_num_allocated() + count as int,
        // MONOTONICITY: Previously allocated frames remain allocated.
        forall|i: int| #![trigger self@.is_allocated(i)]
            0 <= i < self@.capacity() && old(self)@.is_allocated(i) ==>
            self@.is_allocated(i),
```

**Rationale:** The monotonicity property is critical for memory safety reasoning. It explicitly guarantees that batch allocation doesn't affect previously allocated frames. Without this, callers would have to infer it indirectly from the count change. This is a liveness property: "previously allocated frames stay allocated" (good things are preserved).
