### High

- **Missed difference: `PARSE_ERROR_MESSAGE` visibility change.** In the original code
  (line 57), `PARSE_ERROR_MESSAGE` is declared as `const` (private to the module). In
  the verified exec code (line 87), it is declared as `pub const` (publicly visible).
  This widens the public API surface — external code can now access
  `ProcessIdentifier::PARSE_ERROR_MESSAGE`, which was previously impossible. The change
  is likely necessary for Verus `ensures` clauses (which reference
  `Self::PARSE_ERROR_MESSAGE` in postconditions), but it should have been documented as
  a separate TYPE_CHANGE difference in the integrity report with an explicit justification.

### Medium

- **Missed difference: lint configuration block removed.** The original file (lines 8–19)
  has a `#![forbid(...)]` block with 10 clippy/compiler lint directives. The verified exec
  code omits this entirely. While lint directives do not affect runtime semantics, they are
  compile-time safety guards (e.g., `clippy::cast_sign_loss`, `clippy::cast_possible_truncation`)
  that prevent certain classes of bugs. The report should have documented this omission.
  Justification: the verified file is compiled within the Verus crate context where these
  file-level attributes may not apply, and Verus verification provides stronger guarantees
  than clippy lints.

- **Missed difference: static assertion macros removed.** The original (lines 42–43) uses
  `::static_assert::assert_eq_size!(ProcessIdentifier, 4)` and
  `::static_assert::assert_eq_align!(ProcessIdentifier, 4)`. These are replaced by
  `external_body` proof lemmas (`lemma_size_eq_i32`, `lemma_align_eq_i32`). The report
  mentions these lemmas in the Semantic Equivalence Notes section, but does not list the
  removal of the static assertion macros as a separate difference item. The replacement is
  semantically appropriate, but the trust boundary is weaker — `static_assert` is checked at
  compile time unconditionally, while the `external_body` proof lemmas are assumed, not proven.

### Low

- **Missed difference: import path change.** Original uses `use crate::error::{Error, ErrorCode}`
  (line 25–28); verified uses `use crate::libs::error::{Error, ErrorCode}` (line 34–37).
  This is a crate organization difference, not a semantic one, but should be noted for
  completeness since it means the verified code cannot be compiled in the original crate
  without adjustment.

- **Missed difference: constant reordering.** Original order within `impl ProcessIdentifier`:
  `KERNEL_RAW`, `KERNEL`, `PARSE_ERROR_MESSAGE`, `INITD`. Verified order:
  `KERNEL_RAW`, `PARSE_ERROR_MESSAGE`, `KERNEL`, `INITD`. Not semantically meaningful but
  should be documented for traceability.

- **Report references incorrect verified exec path (minor).** The report header says
  `verus/split/kernel/pm/sys/pid.rs`, which is correct for the actual file location, but
  the user-supplied task description referenced `verus/split/libs/sys/sys/pm/` — not a
  report error per se, but worth noting for cross-referencing.
