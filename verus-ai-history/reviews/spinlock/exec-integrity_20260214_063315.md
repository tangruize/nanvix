### 2. LOGIC_CHANGE Correctness (Difference #8)

The sole LOGIC_CHANGE replaces the CAS spin-loop:

```rust
// Original
loop {
    match self.0.compare_exchange(false, true, Ordering::Acquire, Ordering::Relaxed) {
        Ok(false) => break,
        _ => ::arch::cpu::pause(),
    }
}
```

with delegation to `try_lock()` (single-shot CAS model). The justification is sound:

- `lock()` preconditions: `spec_is_unlocked()` ∧ `wf()` ∧ `!token_issued()`
- `spec_is_unlocked()` ⟹ `!self.locked`
- `try_lock()` succeeds when `!self.locked` (if-branch at line 187)
- Therefore, the loop would execute exactly once under these preconditions
- The `opt_token.tracked_unwrap()` on line 226 is safe because `try_lock()` postcondition
  guarantees `result.1@.is_some()` on success

This is verified non-vacuously (Verus checks both paths of `try_lock`). **Correctly justified.**
