## Grade: A-

## Issues Found

### Critical

### High

### Medium

- **Unreported visibility change on struct fields (cosmetic):**
  Original `SleepingThread` has private fields (`state`, `alarm`). The verified
  version makes them `pub` for Verus proof ergonomics. This is mentioned in a
  code comment (sleeping.rs line 106-109) but **not listed** as a numbered
  difference in the report table. Should be a separate `VISIBILITY_CHANGE` row
  for completeness. Impact: none on exec logic (fields are only accessed through
  methods in the original), but breaks encapsulation in the model.

- **Unreported visibility change on `from_state` (cosmetic):**
  Original `from_state` is `pub(super)` (restricted to parent module). Verified
  version is `pub` (fully public). Not reported. Impact: none on exec logic
  semantics, but the report's completeness claim ("Total differences: 14") is
  technically inaccurate — should be 16-17.

### Low

- **Unreported `#[derive(Debug)]` omission:**
  Original struct has `#[derive(Debug)]`; verified version does not. Standard
  for Verus models (Debug is not expressible), but should be documented for
  completeness alongside the other structural differences.

- **Boundary model `ReadyThread.wf()` omits `admission_time >= 0`:**
  The boundary `ReadyThread::wf()` spec (sleeping.spec.rs line 185-187) only
  checks `self.state.wf()` but not `self.admission_time >= 0`. The exec
  `from_state` ensures `spec_admission_time() >= 0` via postcondition, but
  `wf()` itself doesn't encode this invariant. If a proof were to construct a
  `ReadyThread` directly with a negative `admission_time`, `wf()` would still
  hold. This is a minor spec completeness gap, not an exec integrity issue.
