### Medium

- **`pub bits` field exposure is understated in risk classification.** The report categorizes this as TYPE_CHANGE (#3) but the field visibility change from private `(u8)` to `pub bits: u8` is the most significant semantic deviation in the entire module. While the report extensively documents the Verus constraint and lists attempted alternatives (`pub(crate)`, `pub(super)`, closed spec fn — all rejected), external code can now construct `Capabilities { bits: 0xFF }` bypassing the API entirely. The `wf()` invariant is proof-level only and provides no runtime protection. The report acknowledges this in the "Known deviation" section but classifies the item at the same severity as adding `PartialEq`/`Eq` derives. For traceability, this should be flagged distinctly as the sole API-surface deviation. **Impact: Low in practice** — downstream verified modules would need to satisfy `wf()` preconditions, and unverified code could already bypass the original API via `unsafe`. No fix needed, but future audits should note this.

### Low

- **Report omits explicit operator-precedence analysis for `1 << capability as u8`.** The equivalence between `to_mask(capability)` and `1 << capability as u8` depends on Rust's precedence rules: `as` binds tighter than `<<`, so it is `1 << (capability as u8)`, not `(1 << capability) as u8`. The report states the equivalence is "proven by `lemma_mask_matches_discriminant`" but does not explain *why* the original expression produces the expected values. The lemma proves `spec_mask(cap) == spec_pow2_mask(cap.spec_discriminant())` which is correct, but the connection from the original source's `1 << capability as u8` (which depends on Rust's `as`-cast producing the discriminant, and `<<` on `u8` being non-wrapping for shifts ≤ 4) to `spec_pow2_mask(discriminant)` is left implicit. This is a documentation gap, not a correctness issue.

- **`new()` constructor duplicates `Default::default()` body.** Both return `Capabilities { bits: 0u8 }` with identical postconditions. The report justifies `new()` as "supplements (does not replace)" Default, which is correct but slightly redundant. Minor — no action needed.
