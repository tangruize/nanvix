# Review: running_process Exec Integrity (claude-opus-4.6)

## Grade: A

## Issues Found

### Critical
- None.

### High
- None.

### Medium

1. **Undocumented added precondition on `find_thread_mut()`.**
   The verified `find_thread_mut()` adds `requires old(self).wf()` (line 712), but the
   original has no such precondition — it simply searches collections and returns a
   reference. The integrity report does not list this as a difference. In practice this
   is harmless (all callers should maintain `wf()`), and the function body does not
   depend on `wf()` — it only serves to propagate `self.wf() == old(self).wf()` in the
   ensures clause. However, it should have been documented as a GHOST_ANNOTATION
   difference, since it constrains callers beyond the original API contract.

2. **Asymmetry between `find_thread()` and `find_thread_mut()` preconditions.**
   `find_thread()` (line 688) has no `wf()` precondition, while `find_thread_mut()`
   (line 710) does. The original source has identical precondition structure for both
   (none). This inconsistency is cosmetic — `find_thread_mut` needs `wf()` only for
   its frame ensures clause — but could confuse downstream proof consumers.

### Low

3. **Elision of error logging not explicitly documented.**
   The original `try_join_thread()` (line 393) calls `error!()` with diagnostic
   information before returning the "not found" error. The verified code elides this
   entirely. While logging has no state-machine impact, the integrity report should
   have listed it as a minor difference for completeness, since the report otherwise
   enumerates every change including doc comments and field visibility.

4. **`state_mut()` frame condition strength.**
   The verified `state_mut()` (line 491) ensures `self.wf() == old(self).wf()`, which
   is a strong claim for an `external_body` function. The original `state_mut()` returns
   `&mut ProcessState`, which permits arbitrary mutation of ProcessState fields. The frame
   condition is justified (ProcessState mutation cannot affect thread lists), but
   `self.wf() == old(self).wf()` also implicitly asserts that the counts remain unchanged
   after arbitrary mutation through the returned reference — this is sound only because
   the counts are on `RunningProcess`, not `ProcessState`. The report's justification
   (item #10) is correct but terse; a note about why count preservation is guaranteed
   would strengthen the argument.

## Detailed Verification

### 1. Were ALL differences identified?

**Nearly all.** The report identifies 21 differences and 3 helpers, covering type changes,
ghost annotations, field visibility, result type modeling, oracle parameters, and helper
functions. Two minor omissions:
- The added `wf()` precondition on `find_thread_mut()` (Medium #1 above).
- The elision of `error!()` logging in `try_join_thread()` (Low #3 above).

### 2. Were LOGIC_CHANGE items correctly handled?

**No LOGIC_CHANGE items exist** — all 21 differences are TYPE_CHANGE or GHOST_ANNOTATION,
categorized as "Acceptable." This classification is correct. Every type simplification
follows the documented verification model (kernel types → u64/Vec\<u64\>), and every
ghost annotation is a pre/postcondition or invariant that constrains but does not alter
exec behavior.

### 3. Remaining semantic differences?

**None significant.** I performed a function-by-function comparison:

- **`schedule()`**: Running thread appended to end of ready list in both. ✓
- **`sleep()`**: Three branches (ready/interrupted/sleeping) match exactly. The
  `ready_count > 0` check correctly models `self.ready.take().is_some()` given `wf()`. ✓
- **`exit()`**: Zombie ordering `[old..., running, ready...]` matches. Interrupted
  ordering `[original_interrupted..., sleeping_as_interrupted...]` matches. The
  `sleeping_thread_ids: Vec::new()` at line 979 correctly models the always-None
  `self.sleeping_threads.take()` at original line 219 (already consumed at line 208). ✓
- **`exit_thread()`**: Four branches match. The `exit_thread()` bug fix (zombie_threads
  previously lost in interrupted branch) is correctly identified and the original source
  has been patched. Verified code at line 1101–1108 passes `zombie_thread_ids` to
  `InterruptedProcess`, matching the patched original's `Some(zombie_threads)`. ✓
- **`wakeup()`**: Oracle `found` correctly collapses both "sleeping is empty" and
  "sleeping exists but tid not found" into `found == false`. Search loop finds first
  occurrence, removes it, pushes tid onto ready. ✓
- **`try_join_thread()`**: Oracle `tag` encodes the search priority (running → zombie →
  live → not_found). The ZOMBIE branch's linear search, removal, and count decrement
  are correct. Other branches preserve state unchanged. ✓
- **`find_thread()` / `find_thread_mut()`**: Both return ghost values from
  `spec_find_thread()`. Search order (running → ready → interrupted → sleeping → zombie)
  matches original. Frame conditions on `find_thread_mut` are correct. ✓

### 4. Is exec code faithful to original?

**Yes.** All 13 original functions are present. Control flow, branching logic, branch
ordering, and data-structure element ordering match the original in every case. The
verification model (u64/Vec\<u64\>) is a sound abstraction of the original kernel types
for state machine logic verification. The four `external_body` functions are justified
and have appropriate postconditions. The two oracle parameters (`found`, `tag`) are
correctly constrained by Verus-verified preconditions.

### 5. Does verification still pass?

**Yes.** 44 verified, 0 errors. No assume or admit statements. Four `external_body`
functions (3 accessors + 1 boundary model), all justified.
